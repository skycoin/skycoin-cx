0006 Power of two sizes for one instruction bound checks
Status: decided by Synth, D146 (internal sizes powers of two, the stack size limit
a power of two, two paths for program arrays). The two paths of the index
check built in #614. The power of two stack, frame and buffer sizes are not
built.

Problem: a bound check written as two compares (below zero, at or above the
end) costs two compares and two branches.

Change: the stack size limit, frame sizes and buffer sizes are powers of two.
The same rule covers the internal, heavily used structures of the runtime:
the call stack kept for stack traces, and the buffers of the built in IR
interpreter (vm) and the image runner (Synth, messages 778 and 779).
A check against a power of two size 2^k is one AND with the mask
NOT(2^k - 1) and one jump if the result is not zero:
  stack:  (fp + frame) AND NOT(2^20 - 1), jump to stop if not zero
  index:  index AND NOT(2^k - 1), jump to stop if not zero
A negative index has its high bits set, so the same test catches it.
On x86 the test and the jump fuse into one micro-op (test + jnz). On ARM it
is tst + b.ne.

Two paths (Synth, message 781):
  fast path: a size that is a power of two gets the mask check above,
    one AND and one jump. The runtime's internal arrays are always powers
    of two and always take the fast path: the stack, the call stack kept
    for stack traces, caches, frame pointer tables, and the vm and image
    runner buffers.
  slow path: a program array whose declared length is not a power of two,
    for example var a [100]i32, keeps its exact length and gets the
    unsigned compare of 0007 (one compare and one jump, index < 100), so
    indexes 100 to 127 are caught.
The compiler picks the path from the length at build time, so neither
check tests which path it is at run time.

The compiler writes a comment next to each check in the emitted IR, naming
the check and its mask.

Built (index check only): a power of two length gets
  index AND NOT(length - 1), branch if not zero
in the LLVM output, with a comment naming the check and its mask. clang -O2
turns that test into the same unsigned compare as the slow path (cmp +
jae), so on x86-64 both paths compile to one compare and one branch. vm uses
the unsigned compare of 0007 for every length.
